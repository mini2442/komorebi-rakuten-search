# こもれび 商品さがし

非公開の「こもれび投稿ノート」と独立した公開検索用プロジェクトです。
公開検索専用の登録URL・公式IP18個・登録目的を照合後、2026-10-23に公開検索だけの通信を有効化しました。
GitHubにはコードと空の設定見本だけを配置します。認証成功は実通信の結果で判断します。

## 含まれる機能
4テーマの商品検索、ランキング、楽天商品ページへのリンク、取得日時と出典、エラー案内。
元アプリの providers.py / rakuten_settings.py の接続・解析を再利用しています。
DB・Supabase・投稿管理・ログイン・データ移行・ChatGPT連携は含みません。
取得結果はその閲覧セッションだけに保持し、DBやファイルに永続保存しません。
検索語・アクセス情報がホスティング事業者に処理される可能性まで否定するものではありません。

## ローカルで確認
1. Python環境で requirements.txt の依存を用意します（既存Macの仮想環境も利用できます）。
2. `python -m streamlit run app.py --server.port 8502` で起動します。
3. キーなしでも接続準備中の画面が開きます。キー未設定時の検索ボタンは無効です。
4. `python -m unittest discover -s tests -v` で実通信しないモックテストを実行します。

## 配置・設定
- このフォルダーだけを新しいリポジトリ・別のStreamlitアプリに配置します。
  既存ノートのリポジトリやデータ・バックアップはコピーしません。
  公開アプリ用リポジトリに実キーを記載しません。
- Supabase設定は新アプリのSecretsに登録しません。楽天キーだけ本人が直接入力します。
- 楽天の登録アプリ・URL・許可IPを、この公開検索の実際の構成に合わせて確認します。
- 楽天API利用条件との照合と公開の承認後、別工程で停止枠を解除します。
  現在は room_manager/providers.py の LIVE_API_ENABLED=True。緊急停止時はFalseへ戻して反映します。
  Secretsから通信停止枠を変更する仕組みはありません。
  非公開版の PRIVATE_USE_CONFIRMED フラグを流用して「許可済み」と扱いません。
- 公開URL確定後、非公開ノートのSecretsへ PUBLIC_RESEARCH_URL を追加するとリンクが表示されます。
  架空の公開URLや現在の非公開URLは設定しないでください。

## 制限と規約上の残課題
- 誰でもログインなしに実際に検索できる公開サービスとして運用する必要があります。
  非公開ノート専用の中継を公開URLで偽装する設計ではありません。
- 非公開ノートへのAPI結果自動転送・保存・ChatGPTへの受け渡しは追加していません。
  手動での持ち出しなら無条件に許されるという意味でもありません。
- 第10条1項(7)(9)(10)、第8条4項・7項、第3条について実際の利用を再確認します。
  公開しただけで規約適合と断定しません。API情報の複製・加工・蓄積・外部AIへの提供は別問題です。
- 商品リンクと公式クレジットを表示し、外部SNSリンクは設けません。
- 公開された検索は第三者もAPI枠を消費します。10回/分・100回/時はプロセス単位の共有上限です。
  再起動や複数プロセスをまたぐ厳密な上限・利用者別の制限・DoS防御ではありません。
  初期版は一つの稼働プロセスを前提とし、規模拡大時は共有の制限機構が必要です。
- ホスト提供のアクセスログ等は別管理です。APIキーをログ出力せず、HTTPデバッグを有効にしません。

## 季節の優先表示

ファッションの商品検索で「自動・春・夏・秋・冬・すべて」を選べます。自動は日本時間の月で判定します。
取得した最大30件の商品名の表記で参考順に並べ替え、追加API通信・除外・仕様推測はしません。
秋冬はニットや長袖などを優先し、半袖などの優先度を下げます。季節語の多い商品名などでは誤判定もあります。
季節の適合を保証するものではありません。「すべて」はAPI取得順、ランキングは常に公式順です。
季節変更時は前の結果を消し、検索ボタンを押したときだけ再取得します。
